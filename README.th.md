# Tracebrief

**เปลี่ยนไฟล์ HAR ให้เป็นรายงานเครือข่ายที่ตรวจทานได้ก่อนแชร์**

ดูลำดับคำขอ ข้อผิดพลาด HTTP คำขอที่ช้า และเส้นทางที่ถูกเรียกซ้ำ โดยไม่คัดลอก URL, header, cookie หรือข้อมูลในคำขอและคำตอบจากไฟล์ต้นฉบับลงในรายงาน ทำงานบนเครื่องของคุณผ่านเบราว์เซอร์หรือเทอร์มินัล ไม่ต้องมีบัญชี API key เซิร์ฟเวอร์ส่วนหลัง หรือแพ็กเกจจากภายนอก

## เริ่มใช้งาน

ต้องใช้ **Node.js 22 ขึ้นไป** จากโฟลเดอร์ซอร์สโค้ดที่ดาวน์โหลดหรือโคลนมา ให้รัน:

```sh
git clone https://github.com/hieunguyenak92/tracebrief.git
cd tracebrief
npm run dev
```

เปิด **http://localhost:4173** แล้วเลือกข้อมูลสาธิต หรือลากไฟล์ `.har` ลงในหน้าเว็บ ตรวจสอบแผนภูมิลำดับเวลาของคำขอ แล้วส่งออกรายงานได้ทันที ไม่ต้องติดตั้งแพ็กเกจเพิ่มเติม

หากต้องการไฟล์เดียวที่เปิดได้โดยไม่ต้องรันเซิร์ฟเวอร์:

```sh
npm run build
```

เปิด `dist/index.html` ในเบราว์เซอร์ เมื่อทำงานกับข้อมูลส่วนตัว ให้ใช้สำเนาบนเครื่องที่คุณเชื่อถือ ไฟล์ HAR ต้นฉบับจะอยู่ในอุปกรณ์ของคุณ แอปไม่อัปโหลดไฟล์และไม่เก็บไฟล์ไว้เมื่อโหลดหน้าเว็บใหม่

## สิ่งที่ทำได้

- ดูแผนภูมิลำดับเวลาของคำขอ พร้อมตัวกรองข้อผิดพลาด HTTP/เครือข่าย คำขอที่ใช้เวลาอย่างน้อยหนึ่งวินาที และคำขอซ้ำ
- ดูจำนวนข้อมูลแต่ละประเภทที่ถูกตัดออก เพื่อให้ทราบว่ารายงานไม่ได้รวมอะไรไว้บ้าง
- ส่งออก Markdown สำหรับแนบ issue หรือส่งให้ผู้ช่วยเขียนโค้ดด้วย AI, รายงาน HTML ที่เปิดได้ด้วยตัวเอง และ HAR ที่สร้างขึ้นใหม่จากเมทาดาทา ส่วน JSON เมทาดาทาส่งออกได้ผ่าน CLI
- ใช้แกนวิเคราะห์เดียวกันทั้งในเบราว์เซอร์และ CLI ค่าที่ไม่ทราบจะยังคงระบุว่าไม่ทราบ

“คำขอซ้ำ” หมายถึงคำขอหลังรายการแรกที่มี method, origin และ path เดียวกัน โดยไม่ใช้ query string ในการจัดกลุ่ม การเรียกซ้ำอาจเป็นพฤติกรรมที่ตั้งใจไว้ และคำขอที่ช้าเป็นเพียงสิ่งที่สังเกตพบ ไม่ใช่ข้อสรุปถึงสาเหตุของปัญหา

## ข้อมูลใดถูกแชร์

Tracebrief **สร้างรายงานใหม่จากเมทาดาทาที่อนุญาตให้เก็บไว้เท่านั้น** ไม่ได้แก้ไขไฟล์ต้นฉบับแล้วคาดเดาว่าข้อความใดเป็นความลับ

| ข้อมูลที่เก็บไว้ | ข้อมูลที่ตัดออกหรือแทนที่ |
| --- | --- |
| ลำดับคำขอ เวลาเริ่มแบบสัมพัทธ์ ระยะเวลาทั้งหมด เวลารอ และเวลารับข้อมูล | วันที่และเวลาจริงถูกเปลี่ยนเป็นเวลาสัมพัทธ์ วันที่ใน HAR ที่สร้างใหม่เริ่มจาก 1970-01-01 |
| รหัสสถานะที่ถูกต้อง ขนาดเป็นไบต์ method มาตรฐาน และหมวดหมู่เนื้อหาที่กำหนดไว้ | URL, host, path, query และ fragment ต้นฉบับถูกแทนด้วยชื่อแทนของ origin/route ที่ไม่สื่อความหมาย |
| ความสัมพันธ์ของคำขอตาม origin และ route | ไม่รวม header, cookie, เนื้อหาคำขอ/คำตอบ และฟิลด์ที่กำหนดเพิ่มเติม |

ตัวอย่างเช่น URL จะถูกส่งออกเป็น `https://origin-1.invalid/route-2` ชื่อแทนเหล่านี้ใช้เชื่อมโยงคำขอภายในการวิเคราะห์ครั้งนั้นเท่านั้น ไม่ได้บอกชื่อ endpoint จริง หากต้องการดู URL ต้นฉบับ ต้องเปิดตัวเลือก **ดูบนเครื่องเท่านั้น** โดยชัดเจน URL เหล่านั้นจะไม่ถูกนำไปใช้ในไฟล์ส่งออก

**ตรวจทานไฟล์ส่งออกทุกครั้ง** เวลา ขนาด รหัสสถานะ และรูปแบบการเรียกคำขอยังอาจเป็นข้อมูลอ่อนไหวได้ Tracebrief ไม่รับประกันว่าจะไม่มีข้อมูลส่วนบุคคลหลงเหลืออยู่ และไม่ได้ทำให้ข้อมูลเป็นนิรนาม HAR ที่สร้างใหม่ไม่สามารถเล่นเซสชันซ้ำหรือใช้วินิจฉัยปัญหาในเนื้อหาข้อมูลและการยืนยันตัวตนได้

HAR นี้เป็นเมทาดาทาที่สร้างขึ้นใหม่และสูญเสียรายละเอียดบางส่วน ฟิลด์เวลาบางรายการใช้ค่าทดแทนเพื่อให้เครื่องมืออื่นเปิดได้ ขณะที่หมายเหตุของ Tracebrief เก็บค่าที่บันทึกจริงและระบุค่าที่ไม่ทราบไว้ เครื่องมือ HAR อื่นอาจแสดงค่าทดแทนเหล่านั้นเป็นค่าที่วัดได้ ดูรายละเอียดใน [ขอบเขตความเป็นส่วนตัว (ภาษาอังกฤษ)](docs/PRIVACY.md)

## CLI

ไม่ต้องใช้เซิร์ฟเวอร์หรือเชื่อมต่อเครือข่าย:

```sh
node bin/tracebrief.js public/samples/demo.har --format markdown
node bin/tracebrief.js capture.har --format html --output report.html
node bin/tracebrief.js capture.har --format har --output reconstructed.har
node bin/tracebrief.js capture.har --format json --output metadata.json
```

รูปแบบเริ่มต้นคือ Markdown ซึ่งเขียนไปยัง standard output ใช้ `--help` เพื่อดูตัวเลือก โปรแกรมจะไม่เขียนทับไฟล์ที่มีอยู่แล้ว โปรดเลือกพาธใหม่สำหรับไฟล์ส่งออก และเก็บ HAR ส่วนตัวไว้นอกโฟลเดอร์ซอร์สโค้ด

## วิธีบันทึก HAR

1. เปิดเครื่องมือสำหรับนักพัฒนาของเบราว์เซอร์ แล้วไปที่แผง Network
2. ทำขั้นตอนที่ทำให้เกิดปัญหาอีกครั้ง แล้วใช้คำสั่งส่งออก HAR ของแผงนั้น
3. เปิดไฟล์ที่บันทึกไว้ด้วยสำเนา Tracebrief บนเครื่องที่คุณเชื่อถือ
4. ตรวจสอบรายงานและรายการข้อมูลที่ถูกตัดออก จากนั้นตรวจทานไฟล์ส่งออกก่อนส่งให้ผู้อื่น

Chrome มีตัวเลือกส่งออก HAR ที่ตัด header อ่อนไหวบางรายการอยู่แล้ว Tracebrief ลดรายละเอียดที่นำไปแชร์เพิ่มเติมด้วยการตัด endpoint และเนื้อหาข้อมูลต้นฉบับออกด้วย HAR แบบเต็มอาจมีข้อมูลรับรองการเข้าถึงและข้อมูลส่วนบุคคล ดู [เอกสารแผง Network ของ Chrome (ภาษาอังกฤษ)](https://developer.chrome.com/docs/devtools/network/reference) และ [การเปรียบเทียบเครื่องมือ (ภาษาอังกฤษ)](docs/COMPARISON.md)

## ข้อจำกัด

- รองรับ HAR JSON ขนาดสูงสุด **50 MiB** และ **20,000 รายการ** ต่อไฟล์
- เก็บเฉพาะเมทาดาทาตัวเลขที่ถูกต้องและอยู่ในขอบเขตที่กำหนด ฟิลด์ที่ขาดหายหรือไม่ถูกต้องจะมีคำเตือนหรือระบุว่าไม่ทราบ
- ไม่รองรับการบันทึกทราฟฟิกแบบสด การเล่นเซสชันซ้ำ การเชื่อมโยงชื่อแทนข้ามไฟล์ หรือการอธิบายสาเหตุที่คำขอล้มเหลวโดยอัตโนมัติ
- การตัด endpoint และเนื้อหาข้อมูลออกทำให้รายละเอียดสำหรับแก้บั๊กลดลง หากจำเป็นต้องใช้ข้อมูลเหล่านั้น ให้ใช้ DevTools หรือช่องทางแก้ปัญหาแบบส่วนตัวที่คุณเชื่อถือ
- เวอร์ชัน 0.1 เป็นรุ่นเริ่มต้น ยังต้องการข้อเสนอแนะสำหรับเบราว์เซอร์และระบบปฏิบัติการที่อยู่นอกขอบเขตการตรวจสอบที่บันทึกไว้

## การพัฒนา

```sh
npm test
npm run lint
npm run build
```

โครงสร้างซอร์สโค้ด: `public/core.js` ใช้วิเคราะห์และสร้างไฟล์ส่งออก, `public/app.js` จัดการการโต้ตอบในเบราว์เซอร์ และ `bin/tracebrief.js` เป็น CLI สคริปต์ build และเซิร์ฟเวอร์สำหรับพัฒนาใช้ไลบรารีมาตรฐานของ Node

เมื่อรายงานบั๊ก โปรดส่งตัวอย่าง **ข้อมูลที่สร้างขึ้น** ซึ่งมีขนาดเล็กที่สุดและยังทำให้เกิดปัญหาได้ ห้ามแนบ HAR จากระบบจริง access token ข้อมูลลูกค้า หรือ endpoint ส่วนตัวใน issue สาธารณะ ดู [แนวทางการมีส่วนร่วม (ภาษาอังกฤษ)](CONTRIBUTING.md) และ [นโยบายความปลอดภัย (ภาษาอังกฤษ)](SECURITY.md)
