# Tracebrief

**HARキャプチャを、共有前に確認できるネットワークレポートに。**

リクエストの順序、HTTPエラー、遅いリクエスト、繰り返し現れるルートを把握できます。元のURL、ヘッダー、Cookie、ペイロードはレポートにコピーしません。ブラウザーまたはターミナルでローカルに動作し、アカウント、APIキー、バックエンド、外部パッケージは不要です。

## 試してみる

**Node.js 22以降**が必要です。チェックアウトしたディレクトリで実行します。

```sh
npm run dev
```

[http://localhost:4173](http://localhost:4173)を開き、架空データのデモを選ぶか、`.har`ファイルをページにドロップしてください。ウォーターフォールを確認し、レポートをエクスポートできます。依存パッケージのインストールは不要です。

サーバーなしで開ける単一のHTMLファイルを作る場合：

```sh
npm run build
```

ブラウザーで`dist/index.html`を開きます。非公開のキャプチャを扱う際は、信頼できるローカルコピーを使用してください。元のHARは端末内に残ります。アプリはアップロードせず、ページの再読み込み後まで保持する保存も行いません。

## できること

- HTTP／ネットワークエラー、1秒以上かかったリクエスト、繰り返しのリクエストで絞り込めるウォーターフォール。
- エクスポートから除外されるデータの種類と件数の表示。
- IssueやAIコーディングアシスタント向けのMarkdown、単体で開けるHTMLレポート、HAR 1.2対応ツール向けの再構成HAR。CLIではJSONメタデータも出力できます。
- ブラウザーとCLIで共通の分析コア。不明な測定値を推測で補いません。

「繰り返し」は、同じメソッド・オリジン・パスが初出後に再び現れることを指します。グループ化ではクエリ文字列を無視します。繰り返しのリクエストは意図した動作の場合もあります。リクエストが遅いという観察だけで、根本原因を特定することはできません。

## 共有される情報

Tracebriefは**許可したメタデータから新しいレポートを構築します**。元のファイルを編集しながら、どの文字列が秘密情報かを推測する方式ではありません。

| 保持する情報 | 除外・置換する情報 |
| --- | --- |
| リクエスト順、相対開始時刻、所要・待機・受信時間 | 絶対日時は相対オフセットに変換し、再構成HARの日時は1970-01-01を基準にします |
| 有効なステータスコード、バイト数、標準メソッド、固定のコンテンツ分類 | 元のURL・ホスト・パス・クエリ・フラグメントは、実名を示さないオリジン／ルートの別名に置換します |
| オリジンとルートによるグループ化 | ヘッダー、Cookie、リクエスト／レスポンス本文、独自フィールドは除外します |

たとえばURLは`https://origin-1.invalid/route-2`として出力されます。別名はその分析内でリクエストの関連を表すだけで、実際のエンドポイント名ではありません。元のURLは、明示的に**ローカル表示**を有効にした場合に表示できますが、エクスポートには含まれません。

**共有前に、すべての出力を確認してください。** 時間、サイズ、ステータスコード、リクエストのパターンにも機密性があり得ます。Tracebriefは個人情報が含まれないことや、キャプチャの匿名性を保証しません。再構成HARではセッションを再現できず、ペイロードや認証の問題も診断できません。詳しくは[プライバシーの設計と制限](docs/PRIVACY.md)を参照してください。

## CLI

サーバーもネットワーク接続も不要です。

```sh
node bin/tracebrief.js public/samples/demo.har --format markdown
node bin/tracebrief.js capture.har --format html --output report.html
node bin/tracebrief.js capture.har --format har --output reconstructed.har
node bin/tracebrief.js capture.har --format json --output metadata.json
```

既定の形式はMarkdownで、標準出力に書き出します。オプションは`--help`で確認できます。既存の出力ファイルは上書きしないため、新しいパスを指定してください。非公開キャプチャはチェックアウトしたディレクトリの外で保管してください。

## HARを取得する

1. ブラウザーの開発者ツールでNetworkパネルを開きます。
2. 問題を再現し、パネルのHARエクスポート機能を使用します。
3. 保存したキャプチャを、信頼できるローカルのTracebriefで開きます。
4. レポートと除外項目を確認し、送信前にエクスポートしたファイルも見直します。

Chromeにも、一部の機密ヘッダーを除外するHARエクスポートがあります。Tracebriefは、元のエンドポイントと本文も除外し、共有する情報をさらに限定します。完全なキャプチャには認証情報や個人情報が含まれる可能性があります。[ChromeのNetworkリファレンス](https://developer.chrome.com/docs/devtools/network/reference)と[他のツールとの比較](docs/COMPARISON.md)を参照してください。

## 制限

- 1キャプチャあたりHAR JSON **50 MiB**、**20,000エントリー**まで。
- 有効かつ範囲内の数値メタデータのみを保持します。欠落・不正なフィールドは注意事項や不明値として扱います。
- ライブキャプチャ、リプレイ、異なるキャプチャ間の別名対応付け、リクエスト失敗理由の自動説明は行いません。
- エンドポイントと本文を除外すると、デバッグに使える情報も減ります。必要な場合はDevToolsや信頼できる非公開のデバッグ手段を使用してください。
- バージョン0.1は初期リリースです。記録済みの検証範囲外のブラウザー／OSの組み合わせについては、フィードバックをお待ちしています。

## 開発

```sh
npm test
npm run lint
npm run build
```

`public/core.js`が分析とエクスポート、`public/app.js`がブラウザー操作、`bin/tracebrief.js`がCLIを担当します。ビルド・開発スクリプトはNode標準ライブラリを使用しています。

不具合報告には、**架空データ**を使った最小の再現例を添えてください。本番環境のHAR、アクセストークン、顧客のペイロード、非公開エンドポイントを公開Issueに添付しないでください。[貢献ガイド](CONTRIBUTING.md) · [セキュリティポリシー](SECURITY.md)。
